# Forma — менеджер задач с календарём

Веб-приложение для планирования задач по дням: календарь месяца, приоритеты, категории, заметки, поиск и фильтры. У каждого пользователя свой аккаунт и свой список задач, данные хранятся на сервере в PostgreSQL.

## Возможности

- Регистрация и вход по email и паролю, сессия на 7 дней.
- Календарь месяца (неделя начинается с понедельника), переключение месяцев, быстрый выбор месяца, возврат к сегодняшней дате.
- Панель выбранного дня: добавление, выполнение, редактирование и удаление задач.
- Перенос задачи на другой день перетаскиванием в календаре или через изменение даты.
- Разделы «Просрочено» и «Без даты».
- Приоритеты (низкий, обычный, высокий), категории (работа, учёба, личное, здоровье), заметки до 1000 символов.
- Поиск по названию, фильтры по статусу и категории, сортировка (новые, приоритет, название).
- Счётчик задач месяца и прогресс выполнения.
- Отмена последнего удаления.
- Экспорт и импорт задач в JSON (старым задачам без UUID при импорте выдаются новые идентификаторы).
- Горячие клавиши: N — новая задача, T — сегодня, ← → — смена месяца.
- Адаптивная вёрстка для телефона.
- Индикатор сохранения и сообщения об ошибках связи с сервером.

## Технологии

**Frontend:** React 19, TypeScript 5.7, Vite 6, Lucide React, CSS, шрифт Manrope (Google Fonts).

**Backend:** Node.js 22+, Express 4, PostgreSQL (драйвер `pg`), JWT (`jsonwebtoken`), хэширование паролей `bcryptjs`, защитные заголовки `helmet`, ограничение попыток входа `express-rate-limit`.

**Инструменты:** встроенный тест-раннер Node (`node:test`), Prettier, GitHub Actions (тесты и сборка).

## API

Все маршруты имеют префикс `/api`. Маршруты задач требуют заголовок `Authorization: Bearer <token>`.

| Метод  | Путь             | Описание                         |
| ------ | ---------------- | -------------------------------- |
| GET    | `/health`        | проверка работы сервера          |
| POST   | `/auth/register` | регистрация (email, пароль, имя) |
| POST   | `/auth/login`    | вход                             |
| GET    | `/auth/me`       | текущий пользователь             |
| GET    | `/tasks`         | список своих задач               |
| POST   | `/tasks`         | создать задачу                   |
| PATCH  | `/tasks/:id`     | изменить задачу                  |
| DELETE | `/tasks/:id`     | удалить задачу                   |

Идентификаторы задач — UUID. Название — до 180 символов, заметка — до 1000. Пароль — от 8 символов, не больше 72 байт (около 36 русских букв). На вход и регистрацию действует лимит: 10 попыток с одного IP за 15 минут.

## Настройки сервера (`server/.env`)

| Переменная     | Описание                                                                               |
| -------------- | -------------------------------------------------------------------------------------- |
| `DATABASE_URL` | строка подключения к PostgreSQL                                                        |
| `JWT_SECRET`   | секрет для подписи токенов, не короче 16 символов (`openssl rand -hex 48`)             |
| `PORT`         | порт сервера, по умолчанию 3001                                                        |
| `HOST`         | адрес прослушивания, по умолчанию `0.0.0.0`; за nginx ставьте `127.0.0.1`              |
| `TRUST_PROXY`  | число прокси перед сервером (за nginx — `1`), нужно для лимита попыток по реальному IP |
| `DATABASE_SSL` | `true` для облачных баз (Neon, Supabase и т. п.)                                       |

Таблицы создаются автоматически при первом запуске.

## Локальный запуск

Нужны Node.js 22+ и PostgreSQL.

```bash
createdb forma
cp server/.env.example server/.env     # впишите свои DATABASE_URL и JWT_SECRET

npm ci && (cd server && npm ci)

# терминал 1 — API
cd server && npm run dev

# терминал 2 — фронтенд (проксирует /api на порт 3001)
npm run dev
```

## Production

Сервер сам раздаёт собранный фронтенд из `dist/`, поэтому достаточно одного процесса:

```bash
npm ci && npm run build
cd server && npm ci --omit=dev && npm start
```

Работать по сети нужно через HTTPS: браузер даёт `crypto.randomUUID()` только в безопасном контексте, без него не добавляются задачи. Обычно перед приложением ставят nginx с сертификатом Let's Encrypt. Пошаговая инструкция для VPS — в документе по деплою.

## Безопасность

- Пароли хранятся в виде bcrypt-хэшей.
- Токены JWT (HS256) живут 7 дней и хранятся в localStorage браузера.
- Каждый запрос к задачам фильтруется по владельцу.
- Тело запроса ограничено 100 КБ, на вход и регистрацию действует лимит попыток.
- Защитные заголовки выставляет `helmet`.

## Ограничения

- Импорт JSON заменяет все текущие задачи файлом.
- Отзыва токенов и сброса пароля нет.
